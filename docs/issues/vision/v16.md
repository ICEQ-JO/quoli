# V16 — Version model prices and calculate inspectable cost estimates

Status: published to Quolii as [QUO-52](https://linear.app/quolii/issue/QUO-52/v16-version-model-prices-and-calculate-inspectable-cost-estimates); execution status lives in Linear. Relative size: **M**. Phase: **1 — Contracts and compatibility**.

## Vision alignment and user value

Advances **P4**. User value: version model prices and calculate inspectable cost estimates so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Understanding/pricing**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Define an effective-dated price catalog with currency, model aliases and category units; calculate list-price estimates from resolved reported usage and expose input formula/catalog version.

## Non-goals

Live exchange-rate conversion or a billing ledger.

## Dependencies

V15. These are local draft IDs. Replace with links to existing or newly published **Quolii** issues before starting; do not infer a dependency is complete because its code appears in the tree.

## Acceptance criteria

- Known fixture prices produce repeatable decimal-safe estimates; unknown model/date/category/currency yields an unpriced or partial state; old estimates stay explainable after catalog updates.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Use synthetic prices for cache tiers, date boundaries, alias ambiguity, rounding and missing categories; verify real catalog sources before shipping them.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Separate list-price estimate, provider-reported amount and subscription cost; no invoice claims.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
