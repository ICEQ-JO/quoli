# V07 — Persist and read mixed-version evidence without rewriting history

Status: published to Quolii as [QUO-43](https://linear.app/quolii/issue/QUO-43/v07-persist-and-read-mixed-version-evidence-without-rewriting-history); execution status lives in Linear. Relative size: **M**. Phase: **1 — Contracts and compatibility**.

## Vision alignment and user value

Advances **P2, P3; Commercial: data controls**. User value: persist and read mixed-version evidence without rewriting history so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Evidence/storage**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Add explicit migrations/read compatibility for v2 and preserve original v1 bodies, sequences and provenance. Make derived views version-aware; document backup and failed-upgrade recovery.

## Non-goals

A database replacement or broad storage abstraction.

## Acceptance criteria

- A disposable v1 store upgrades and reads old/new records; retry deduplication, deletion and project isolation remain valid; migration failure preserves recoverable history.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Upgrade a synthetic old database, append v2, restart and compare original bodies; inject migration failure and exercise lifecycle tests.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Never copy private history into fixtures; backups inherit local permissions and deletion documentation.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
