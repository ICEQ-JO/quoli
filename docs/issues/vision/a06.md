# A06 — Detect bounded duplication and report explainable candidates

Status: published to Quolii as [QUO-11](https://linear.app/quolii/issue/QUO-11/a06-detect-bounded-duplication-and-report-explainable-candidates); execution status lives in Linear. Relative size: **M**. Phase: **5**.

## Vision alignment and user value

Advances **P7**. Outcome: detect bounded duplication and report explainable candidates so developers can inspect and rely on their agent evidence in the hosted Quoli workspace. [Canonical vision](../../vision.md).

## Scope and ownership

Owner lane: **Architecture/policy**. Add deterministic normalized syntax duplication detection over changed/scope-bounded code, with exact matching ranges, configurable approved thresholds and exclusions. Keep ambiguous candidates advisory.

Before coding, enumerate affected callers, tests, fixtures, config and docs. Reuse existing packages; replace or delete old paths only after parity and reference checks. Keep local demo and v1 evidence compatibility where affected.

## Non-goals

Whole-web plagiarism search or automatic refactoring.

## Dependencies

V22, A04. Local IDs map to published Quolii issues in the index; prerequisite completion must be demonstrated, not inferred from file existence.

## Acceptance criteria

- Known duplicates match both ranges; generated/vendor/excluded code is omitted explicitly; harmless similarity fixtures measure false positives.
- Demonstrate the bounded behavior with synthetic evidence; record supported versions, omissions, validation and material limitations.
- Update the relevant implementation reference and issue status only after verified results; the vision itself is not delivery evidence.

## Test plan

Run duplicate/near-match/nonduplicate/generated fixtures and bounded large inputs; verify stable ranges and runtime.

Run meaningful affected checks and record actual outcomes. Documentation/design decisions use source/link/threat-model review, not invented application test results.

## Privacy and security

Do not upload source to an external similarity service; no automatic block from vague similarity.

Capture consent and cloud upload consent are separate. Every stored/queued/uploaded field respects its policy before persistence/transmission and cloud revalidation. Preserve append-only evidence and recorded/derived/inferred basis. Missing values stay null/explicit gaps; captured content is inert. Tenant/device scope comes from authenticated identity, never a trusted client claim. Use only synthetic fixtures, never private sessions or credentials.

## Delivery

Select this Quolii issue, use an isolated branch/checkout and produce a reviewed PR with the pillar/gate, linked issue, final behavior, checks and limitations. Supporting agents own bounded areas, do not publish/merge/change owner config, and send no private sessions/code to external prompts. Primary review and meaningful reruns precede integration. No merge, customer-data upload or production deployment is authorized by issue creation.
