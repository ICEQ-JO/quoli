# V27 — Export selected sanitized evidence with provenance and deletion coverage

Status: published to Quolii as [QUO-63](https://linear.app/quolii/issue/QUO-63/v27-export-selected-sanitized-evidence-with-provenance-and-deletion); execution status lives in Linear. Relative size: **M**. Phase: **4 — Paid-pilot gates**.

## Vision alignment and user value

Advances **P6; Commercial: data controls**. User value: export selected sanitized evidence with provenance and deletion coverage so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Evidence/export**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Provide an explicit local export of selected review evidence and scene/narrative with schema versions, gaps and an inspectable content preview. Include derived/cache data in retention/deletion inventory.

## Non-goals

Hosted sharing, accounts or general import/replay.

## Dependencies

V03, V07, V19, C11, C14. These are local draft IDs. Replace with links to existing or newly published **Quolii** issues before starting; do not infer a dependency is complete because its code appears in the tree.

## Acceptance criteria

- Export selection and omissions are visible; selected content can be excluded independently; package is self-describing and safe to inspect offline.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Export fixture sessions with disabled/redacted/deleted fields, hostile text and missing references; verify no unrelated project data.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Warn in the product that exported copies leave Quoli deletion control; never auto-upload or execute bundled content.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.

## Delivery

Select the concrete Quolii issue before implementation. Use an isolated branch/checkout and a PR that names this pillar/gate, final behavior, linked Linear issue, checks and material limits. Primary-agent review is required for supporting-agent output. No merge is authorized by this draft.

## Hosted delivery integration

The target surface is the authenticated Quoli cloud dashboard with paired local connectors. Local capture stays useful offline; upload needs separate category consent. UI work uses authorized cloud queries and tenant-scoped caches; source work emits the shared connector contract. Keep the synthetic/local demo working. Do not expose the loopback collector publicly. Architecture and debt work are concrete A-prefixed implementation issues, not an unspecified future product.
