Advances **P2, P3; Commercial: observability**. User value: measure pilot capacity and expose query limits without silent loss so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Acceptance criteria

- A documented pilot load has measured latency/storage; truncated lists are explicit and navigable; exceeding caps cannot produce apparently complete totals.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Generate non-private load fixtures including wide subagent trees and long sessions; measure memory/latency and test cap boundaries.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Benchmarks use synthetic data; no payload logging or raising limits without resource bounds.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
