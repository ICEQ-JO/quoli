# V08 — Define adapter registration, capabilities and conformance fixtures

Status: published to Quolii as [QUO-44](https://linear.app/quolii/issue/QUO-44/v08-define-adapter-registration-capabilities-and-conformance-fixtures); execution status lives in Linear. Relative size: **M**. Phase: **1 — Contracts and compatibility**.

## Vision alignment and user value

Advances **P2**. User value: define adapter registration, capabilities and conformance fixtures so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Sources/contracts**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Define a minimal adapter contract covering source identity, supported versions, capabilities, event mapping, durable delivery identity, failure/gap reporting and reversible installation. Wrap existing Claude behavior through it.

## Non-goals

A dynamic plugin loader or speculative support claims.

## Dependencies

V06. These are local draft IDs. Replace with links to existing or newly published **Quolii** issues before starting; do not infer a dependency is complete because its code appears in the tree.

## Acceptance criteria

- One shared fixture suite checks Claude and a synthetic second adapter; unsupported versions fail explicitly; installed versus supported state is inspectable.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Test retries, late arrival, missing IDs/results, unknown versions and install/uninstall without a paid harness.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

No session content or credentials in discovery logs; adapters respect lifecycle controls before persistence.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.

## Delivery

Select the concrete Quolii issue before implementation. Use an isolated branch/checkout and a PR that names this pillar/gate, final behavior, linked Linear issue, checks and material limits. Primary-agent review is required for supporting-agent output. No merge is authorized by this draft.

UI work uses authorized cloud queries and tenant-scoped caches; source work emits the shared connector contract. Keep the synthetic/local demo working. Do not expose the loopback collector publicly.
