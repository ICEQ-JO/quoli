# V13 — Connect GitHub with least-privilege repository credentials

Status: published to Quolii as [QUO-49](https://linear.app/quolii/issue/QUO-49/v13-connect-github-with-least-privilege-repository-credentials); execution status lives in Linear. Relative size: **M**. Phase: **2 — Sources and activity**.

## Vision alignment and user value

Advances **P1; Commercial: data controls**. User value: connect GitHub with least-privilege repository credentials so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Sources/GitHub auth**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Implement the approved read-only GitHub connection flow and OS-keychain local credential storage; cloud repository app credentials use scoped encrypted secret storage with expiry/revocation handling. Show scopes, repository selection and disconnect behavior.

## Non-goals

Write scopes, repository mutation or hosted token custody.

## Acceptance criteria

- Connect/disconnect works against a fake provider; denied or expired credentials have recovery states; secrets never enter SQLite, URLs or logs.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Mock authorization callbacks/device flow as selected; test wrong state, denied scope, expiry, revocation and unavailable keychain.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Verify official provider/auth contracts before implementation; fail closed when secure token storage is unavailable.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
