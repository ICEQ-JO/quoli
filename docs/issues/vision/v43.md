# V43 — Evaluate optional cited model summaries without weakening the deterministic view

Status: published to Quolii as [QUO-79](https://linear.app/quolii/issue/QUO-79/v43-evaluate-optional-cited-model-summaries-without-weakening-the); execution status lives in Linear. Relative size: **M**. Phase: **5 — Full-product expansion**.

## Vision alignment and user value

Advances **P6**. User value: evaluate optional cited model summaries without weakening the deterministic view so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Understanding/summary experiment**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Only if approved, evaluate a model summary over explicitly selected sanitized evidence. Validate citations and label unsupported claims; keep deterministic narrative available and primary.

## Non-goals

Making model output authoritative or shipping before evaluation.

## Dependencies

V01, V20, V27, V34. These are local draft IDs. Replace with links to existing or newly published **Quolii** issues before starting; do not infer a dependency is complete because its code appears in the tree.

## Acceptance criteria

- Evaluation records citation failure/omission behavior and cost; disabled mode performs no model calls; uncited claims cannot replace the factual view.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Use synthetic adversarial prompt-injection content, invalid citations, deleted evidence, refusal and timeout cases; compare to deterministic output.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Separate explicit model/data consent is required; no automatic upload of code/prompts or hidden-reasoning request.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
