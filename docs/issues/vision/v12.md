Advances **P1**. User value: define repository-provider observations and bounded reads so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

Define local/remote repository identity, ref/commit/PR selection, tree/blob/comparison responses, read-only operations and explicit denied/truncated/stale/rate-limited states. Adapt the existing local capture interface where useful.

## Acceptance criteria

- Local fixtures still work; provider-neutral responses preserve ref/commit and missing-path state; a fake remote demonstrates bounded reads.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Test incomplete trees, moving refs, deleted/binary files and provider identity collisions with fake responses.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Credentials are separate from event bodies; a remote fetch is an observation, not a complete audit.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
