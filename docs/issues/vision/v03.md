## Vision alignment and user value

Advances **Commercial: data controls**. User value: fence and remove retries during project lifecycle changes so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Evidence/storage + bridge**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Coordinate project-scoped spool cleanup with purge, retention and policy changes; bind pending deliveries to a project registration generation. Preserve unrelated project records and report bounded capture loss.

## Non-goals

## Acceptance criteria

- Purge removes project retry data; old-generation retries cannot reappear after re-registration; interrupted cleanup is repeatable.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Use two synthetic projects and concurrent append/drain/purge cases; interrupt cleanup, resume and re-register; assert no resurrection or cross-project deletion.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

Fence producers before deletion; cover spool and later cache/derived-data paths.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
