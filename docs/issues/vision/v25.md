# V25 — Connect repositories and harnesses through a capability-aware onboarding flow

Status: published to Quolii as [QUO-61](https://linear.app/quolii/issue/QUO-61/v25-connect-repositories-and-harnesses-through-a-capability-aware); execution status lives in Linear. Relative size: **M**. Phase: **4 — Paid-pilot gates**.

## Vision alignment and user value

Advances **P1, P2; Commercial: onboarding**. User value: connect repositories and harnesses through a capability-aware onboarding flow so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Experience/onboarding**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Extend ConnectionGuide to detect approved harnesses read-only, connect local/GitHub repositories, preview capture consent and produce a useful first synthetic or authorized review. Show unsupported versions and recovery actions.

## Non-goals

Inventing support for detected but unverified harnesses.

## Dependencies

V10, V11, V14, V24. These are local draft IDs. Replace with links to existing or newly published **Quolii** issues before starting; do not infer a dependency is complete because its code appears in the tree.

## Acceptance criteria

- A new user can distinguish repository history from agent capture; metadata-only and code-enabled paths work; disconnect preserves unrelated settings.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Browser/CLI-check empty install, one/two harnesses, remote denial, unsupported version and reconnect; run the agreed fresh-machine walkthrough.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

No silent config installation, full transcript import or source upload; installation stays explicit and reversible.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.

## Delivery

Select the concrete Quolii issue before implementation. Use an isolated branch/checkout and a PR that names this pillar/gate, final behavior, linked Linear issue, checks and material limits. Primary-agent review is required for supporting-agent output. No merge is authorized by this draft.

## Hosted delivery integration

The target surface is the authenticated Quoli cloud dashboard with paired local connectors. Local capture stays useful offline; upload needs separate category consent. UI work uses authorized cloud queries and tenant-scoped caches; source work emits the shared connector contract. Keep the synthetic/local demo working. Do not expose the loopback collector publicly. Architecture and debt work are concrete A-prefixed implementation issues, not an unspecified future product.
