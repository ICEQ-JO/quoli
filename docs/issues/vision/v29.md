# V29 — Install verified updates with rollback and data compatibility

Status: published to Quolii as [QUO-65](https://linear.app/quolii/issue/QUO-65/v29-install-verified-updates-with-rollback-and-data-compatibility); execution status lives in Linear. Relative size: **M**. Phase: **4 — Paid-pilot gates**.

## Vision alignment and user value

Advances **Commercial: distribution, data controls**. User value: install verified updates with rollback and data compatibility so the developer can rely on the agreed evidence and product boundaries. Pillar definitions: [vision](../../vision.md).

## Scope and ownership

Suggested owner lane: **Release/updater**. Bound implementation to this increment; enumerate touched callers, fixtures, config and documentation before coding.

Add explicit signed update verification, supported runtime checks, atomic install switching and recoverable rollback around the existing managed CLI. Document database downgrade restrictions.

## Non-goals

Unattended forced updates or source-tree migration.

## Dependencies

V07, V28. These are local draft IDs. Replace with links to existing or newly published **Quolii** issues before starting; do not infer a dependency is complete because its code appears in the tree.

## Acceptance criteria

- Failed verification leaves the working install untouched; interrupted update recovers; update cannot silently discard evidence or roll an incompatible database backward.
- Record the demonstrated result, unsupported cases and validation evidence in the issue and relevant repository reference docs. Target capability alone does not satisfy acceptance.

## Test plan

Test tampered/wrong-platform manifests, interrupted extraction/switch, occupied ports, old CLI data and a successful update in a disposable installation.

Run only meaningful checks for the final change, record actual outcomes and rerun regressions affected by shared contracts. A documentation/discovery task uses source, link and decision review rather than invented application tests.

## Privacy and security

No untrusted post-install commands; verify paths and archive traversal before extraction.

Retain append-only provenance; unsupported values stay null or an explicit capability state. Captured text is inert untrusted data. Synthetic fixtures contain no real private sessions or credentials.
